# Plan 2: VITS teacher

> **Status:** completed. The InfoRe1 teacher (VITS, 23.7M parameters, OOD CER 0.015) was used to distill the released Vietnamese prototype models. Later experiments with LEMAS pretraining and a VietBibleVox teacher were stopped; new voices follow the [bilingual plan](2026-11-16-bilingual-vi-en.md).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Vietnamese VITS teacher, trained on filtered InfoRe1 with the project's spelling-based token set, that passes the teacher gate: out-of-domain CER ≤ 0.033, held-out CER ≤ the CER of Piper 25h, and passes the maintainer's listening test.

**Architecture:** Vendor the `vits/` part of `rhasspy/piper` (MIT) into `src/vtts/teacher/vits/`, replacing the Cython `monotonic_align` with a numba version (the MAS algorithm from the VITS paper). The training loop is written in plain PyTorch (no Lightning), with AMP fp16 and resume support. Warm-start from the Piper checkpoint `vi_VN/vais1000/medium` (CC-BY-4.0, 919k steps): keep all weights, including the 256-row embedding table (the project's IDs are < 65, so the table is shared, not reinitialized). Periodic automatic evaluation with `scripts/eval/eval_dir.py` on the GPU, selecting the best checkpoint by CER.

**Tech Stack:** PyTorch 2.15 (CUDA 13.2), numba, librosa (mel), RTX 3060 Ti 8 GB (dedicated GPU machine).

**Spec:** `docs/design/specs/2026-11-14-vietnamese-tts-p4-design.md` (section 5.4, section 6)

## Global Constraints

- All global constraints of Plan 1 still apply.
- Code vendored from Piper keeps its MIT copyright headers, together with `src/vtts/teacher/vits/NOTICE.md`; do not import `piper_train` and do not import `piper-phonemize`.
- Teacher input: `encode(g2p(normalize(text)))`, without sentence splitting (training sentences ≤ 15 s).
- "Medium" configuration: 22,050 Hz, hop 256, win 1024, n_fft 1024, mel 80, inter/hidden 192, filter 768, 6 layers, 2 heads, resblock "2", upsample (8, 8, 4), segment 8192 samples.
- Deterministic inference: `noise_scale=0.667`, `noise_scale_w=0.8`, `length_scale=1.0`, `torch.manual_seed(1234)` before each sentence.
- On the training machine: data in `data/infore1/final`, checkpoints in `artifacts/teacher/<run>/` (relative to the checkout).

## Review Focus

1. Sentences with only 1–2 syllables (`"Có."`, "Yes."): batches with `x_lengths` very short relative to the spec. MAS and the duration loss must not produce NaN. Tested in Task 1.
2. Resume midway (lost SSH, power loss): continue training from the last checkpoint, at the right step, with the right optimizer and scaler state. Tested in Task 3.
3. NaN or Inf in the loss under AMP: skip that step, log it, do not corrupt the checkpoint. Tested in Task 3.
4. Sentence longer than the segment but audio shorter than 8192 samples: must pad safely when slicing the segment. Tested in Task 2.
5. Periodic evaluation must not cause OOM during training: ASR runs in a separate process, after the checkpoint has been written. Handled in Task 5.

### Task 6: Optimization loop (if the gate fails)

Order of levers; each attempt is recorded in `docs/reports/teacher.md`:
1. Train more steps (up to 200k).
2. Loosen or tighten the data filtering threshold (`cer_max` 0.05 / 0.15), then retrain from the best checkpoint.
3. Warm-start from `en_US/lessac/medium` instead of `vais1000` if errors concentrate on tones.
4. Increase `c_mel` or lower `noise_scale` at inference if UTMOS is low but CER is good.

**Plan 2 exit gate:** the teacher passes the CER gate, and the maintainer listens and accepts it. Then write Plan 3 (distillation + C runtime).
