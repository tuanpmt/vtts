# Plan 4: ESP32-P4 — on-chip measurement, optimization, final evaluation loop

> **Status:** completed, with changes. The boards became the Waveshare ESP32-P4-86-Panel and ESP32-P4-NANO (instead of the proposed M5Stack Tab5), the firmware moved to `firmware/esp32/` on ESP-IDF v6.1, and an ESP32-S3 port (Waveshare ESP32-S3-Touch-LCD-2.8) was added. Current numbers: [performance report](../../reports/performance.md); further runtime work: [runtime optimization research](../../reports/runtime-optimization-research.md).

**Goal:** The selected student runs in real time on a real ESP32-P4, its output passes the golden gate on the chip, with a final evaluation report and an A/B listening page.

**Spec:** `docs/design/specs/2026-11-14-vietnamese-tts-p4-design.md` (sections 5.7, 6)

## Already done (early, while waiting for the teacher)

- C99 fp32 + int8 runtime (int16 activations with per-frame scale), streaming that is bit-exact with whole-sentence synthesis.
- C text front-end, matching Python exactly on 22,915 sentences.
- Benchmark firmware `firmware/esp32p4/` builds cleanly with ESP-IDF v5.5.2: 1.32 MB flash (S-vocos int8 model 1.14 MB), 136 KB static RAM.

## Remaining work (needs a board)

1. **Buy a board** (proposed: M5Stack Tab5) and flash the benchmark firmware: record RTF, `arena` and RMS for 4 sample sentences; compare on-chip PCM with the host golden (correlation > 0.98, RMS ratio within 0.80–1.25).
2. **Memory:** already reduced (S-vocos 378 KB at chunk 32, 174 KB at chunk 7; fits in SRAM). Remaining: measure RTF with the arena in SRAM and in PSRAM on the chip.
3. **PIE kernel:** write `vtts_dot_s16s8` with `esp.*` instructions (weak-symbol override in `vtts_kernels_ref.c`), check bit-exactness against the reference C version, re-measure RTF.
4. **Weights:** place them in flash (XIP), in PSRAM, or stage each layer into SRAM; measure all three.
5. **Audio out:** I2S + the board's codec; play the 4 sample sentences.
6. **Evaluation → optimization loop (requested by the maintainer):** evaluate CER/UTMOS/whistle index on the int8 build running on the chip (rendered through the host CLI with the same model), compared with the teacher and the baselines; optimize in this order: decoder size within the on-chip RTF budget, number of joint fine-tuning steps, chunk length.
7. **Final report + A/B listening page** (baselines, teacher, fp32 student, on-chip int8 student).
